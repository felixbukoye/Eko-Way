# Lagos Transit Navigator — Route Graph v1.0

## What this pack contains
- `route_graph.json`: nodes, directed ride legs, exact terminal interchange nodes, and proximity transfer candidates.
- `nodes.csv`: unique stop nodes keyed by source `stop_id`.
- `ride_edges.csv`: one row per deduplicated directional route pattern.
- `route_patterns.json`: full route patterns including ordered stop sequence and observed trip times.
- `route_trace_geometries.geojson`: all matched historical LineString traces, linked to graph edges by `edge_id`.
- `exact_terminal_interchanges.csv`: nodes used as the end of at least one route and origin of another, sharing the same source stop ID.
- `proximity_transfer_candidates.csv`: distinct terminal stop IDs within 100 m straight-line distance. These are not active transfer edges.
- `external_flm_corridor_candidates.csv`: relevant LAMATA-published FLM route names, held separately because the public listing does not provide exact stop IDs or geometry.
- `route_planner.py`: standard-library research-mode route query prototype.
- `routePlanner.ts`: TypeScript planner module designed for a Next.js backend; it defaults to no public routes.
- `schema_postgis.sql`: starter PostGIS schema, including a separate table for the 162 captured route LineStrings.
- `hub_pair_research_summary.csv`: all 30 directed MVP hub-pair query checks.
- `hub_pair_research_paths.json`: up to three historical route candidates per directed pair.
- `integrity_tests.csv`: checks for disabled public routing, Keke class integrity and conservative boarding assumptions.
- `graph_statistics.json`: build statistics.

## Source and date scope
Built from the user-supplied `Lagos_GeoPackage_V2.gpkg` via `Lagos_MVP_Phase2_Candidate_Stop_Events.csv`, with historical feed period 2022-11-24 to 2023-12-31.

## Key modelling decisions
1. A graph node is a source `stop_id`. Stop names are not used to merge nodes, because two similarly named terminals may be physically distinct.
2. A directed ride edge represents a deduplicated observed trip pattern from its first stop to its last stop. The full intermediate stop sequence is retained.
3. No intermediate stop is assumed boardable or alightable. The source provides stop sequence and role flags but not explicit pickup/drop-off permissions per trip.
4. Exact same-stop-ID terminal joins are structurally connected. They still require field verification before public directions.
5. Nearby terminal stops with different IDs are listed as possible pedestrian transfers only. Their straight-line proximity does not prove a safe or walkable path.
6. No route is enabled for public routing. Every ride edge is `historical_unverified`.
7. Korope routes touching Lekki/Sandfill are flagged for regulatory review; the graph does not treat them as currently authorised.
8. Fares are not generated by this graph. The historical fare data needs separate interpretation and fresh verification.
9. LAMATA First/Last Mile corridor names are recorded separately as official external candidates, but not connected to graph nodes until exact endpoints and current service are verified. The published scheme describes 11–13 seat minibuses and lists CMS–Obalende, Ojuelegba–Costain and Sandfill–The Palms among its corridors.

## Run a research query
```bash
python route_planner.py --from-hub Yaba --to-hub "Lekki Phase 1" --research-mode
```

The TypeScript function is `planRoutes(graph, fromHub, toHub, { researchMode: true })`. Do not set `researchMode: true` in a public-facing route API until the relevant routes have been field-verified and enabled.

Include proximity candidates (still unverified):
```bash
python route_planner.py --from-hub Yaba --to-hub CMS --research-mode --allow-proximity-transfers
```

Do not use the output as live travel instructions. The graph is a route-research prototype only.

## Current limitations
- Source feed is historical (2022–2023), not live.
- Keke is not represented in the source dataset.
- Public transit directions must remain disabled until each corridor's current service, boarding/alighting permission, transfer walk, operating periods and legality are verified.
- Data ownership and commercial reuse rights must be confirmed with the relevant data owner before product deployment.
