01 — Foundations

Brand & principles

Eko Way is the passenger's instrument for a system that is loud, informal and constantly rerouting. The design answers that with one high-confidence colour, hard edges and typography that reads in glare and traffic.

The promise

“Know your way before you move.” Every screen answers one of three questions: where is it, what does it cost, am I on time.

Who it is for

Daily commuters, students and traders who already read the street. They need speed and certainty, not hand-holding.

Where it lives

Android-first, mid-range devices, patchy data, bright sun, one thumb, 15 seconds of attention at a bus stop.

Six principles

01

Legible in sunlight

No 12px grey on grey. Body text is 16px minimum and every pairing clears 4.5:1 — checked, not assumed.

02

One decision per screen

A route search, a fare, a driver. When a screen asks for two decisions, it becomes a sheet.

03

Yellow means act

The brand colour is a signal, not wallpaper. If it is yellow, it is tappable, live or in motion.

04

Numbers are the interface

Fares, ETAs, stops and seat counts use tabular display figures so they line up and never jitter.

05

Works with no signal

Cached routes, offline tickets, explicit stale states. Never a blank screen and a spinner for 20 seconds.

06

Street, not Silicon Valley

Hand-painted signage, hard shadows, real place names. No glassmorphism, no lavender gradients.

Motion

Nothing over 380ms

Motion should feel like a bus pulling in: quick to arrive, decisive, then still. Hover the rails below to compare easings. Everything collapses to 0ms under prefers-reduced-motion — the tokens already handle it.

17 — Product

Core flows

Three jobs cover 90% of use. Each flow is deliberately short: the target is a ticket in under 60 seconds and 5 taps from a cold open.

A · Catch the next danfo

Primary
  1. Home → tap search or a Nearby stop
  2. Map opens with live vehicles and your blue dot
  3. Tap a vehicle → sheet shows ETA, fare, seats
  4. Book this seat → choose fare → pay
  5. Ticket issued → saved offline → scan at stand

5 taps · target 45s · failure path: cash reserve (no card needed)

B · Plan a journey

Secondary
  1. Route block: from → to (or use current location)
  2. Compare modes with chips: danfo / BRT / keke
  3. Route detail shows stop-by-stop timeline + traffic
  4. Select seats → same checkout as flow A

Fare and duration are always shown together — never one without the other

C · Travel with no data

Critical path
  1. Offline banner states the cache time
  2. Saved routes still resolve from cache
  3. Tickets open from local storage, QR renders offline
  4. Booking attempt queues and explains itself

No dead ends: every offline screen offers a next step

18 — Product

Content & voice

Sound like a well-informed friend who knows the road, not a company. Short sentences, real place names, no exclamation marks. Naira always with the symbol and no decimals: ₦650, never NGN 650.00.

Voice attributes

  • Clear — one idea per sentence. Plain words over jargon.
  • Local — danfo, keke, conductor, stand, along. Use the words people use.
  • Calm — a delay is stated, not dramatised.
  • Honest — if a number is an estimate, say “approx.”.

Microcopy patterns

ButtonVerb + object: “Book this seat”
EmptyState + next step: “No tickets yet — book a seat…”
ErrorWhat happened + what to do: “Payment failed. Try another method.”
Time“6 min”, “08:42”, never “0h 6m”
Fare“₦650”, tabular, no decimals

Say / don't say

  • ✓ “Danfo leaves when it fills.”
    ✕ “Vehicle departure is demand-based.”
  • ✓ “You're offline. Showing routes saved at 08:12.”
    ✕ “Network error (E_NET_004).”
  • ✓ “4 seats left”
    ✕ “Hurry! Only a few spots!!”

19 — Product

Accessibility

WCAG 2.2 AA

Our users include people who cannot read a moving screen at arm's length in daylight. AA is the floor, and the checks below are the ones that actually get broken.

Colour & contrast

  • Body text ≥ 4.5:1; large text ≥ 3:1.
  • Controls and focus rings ≥ 3:1 against their surroundings.
  • State is never colour-only: pair with a label, icon, border or weight.

Touch & pointer

  • Minimum target 44×44 (48 preferred); 8px between targets.
  • No gesture-only actions — every swipe has a button equivalent.
  • Actions reachable with one thumb: primary CTA in the bottom third.

Type & zoom

  • 16px minimum body on mobile.
  • Layout survives 200% text zoom without clipping.
  • No text inside images — everything is real text.

Motion

  • prefers-reduced-motion turns all durations to 0ms.
  • No animation loops except the live pulse, which stops when data is stale.
  • Nothing flashes more than 3 times per second.

Screen readers

  • Tabs announce state (aria-selected); sheets trap focus and close on Escape.
  • Icons are decorative unless they are the only label — then they get an accessible name.
  • Fare and ETA updates announce politely, never interrupt.

Environment

  • Outdoor mode: contrast targets met at 100% brightness in sun.
  • Offline states are explicit — no fake live indicators.
  • Low-end device budget: no blur above 6px, no continuous animation on map.

20 — Product

Handoff

Tokens live in styles/tokens.css and are mirrored in tokens.json for Figma, React Native and native. Components consume semantic aliases only — that rule is what keeps design and code in sync.

Token pipeline

styles/tokens.css → CSS custom properties (web) tokens.json → Figma variables / RN theme / iOS, Android docs/DESIGN-SYSTEM.md → the rules and rationale index.html → this living style guide

Change a raw value in one place. Both the guide and the product follow.

Naming contract

--{category}-{role}-{step} --yellow-400 raw ramp value (never in components) --bg-brand semantic alias (use this) --text-secondary --space-4 --radius-lg --duration-base

Definition of done

  • No hard-coded hex, px colour or font size in a component.
  • All four states designed: default, loading, empty, error.
  • Contrast verified, focus visible, 44px targets.
  • Reduced motion and 200% zoom checked.
  • Copy reviewed against voice rules.

What is deliberately out of scope for v1

Dark mode Driver app Tablet / desktop layouts Illustration system Data-viz for admin Yoruba / Pidgin localisation

Dark-mode tokens already exist in tokens.css under [data-theme="dark"]; the rest are queued for v1.1 – v2.
